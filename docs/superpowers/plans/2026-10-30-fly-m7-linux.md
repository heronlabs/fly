# fly M7 — Linux Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fly runs on Linux desktops (Ubuntu 22.04+, Debian 12+; x64 and arm64), shipped as a `.deb` on every release next to the macOS dmg.

**Architecture:** Core, tmux, git, gh, node-pty and the transcript reader already work on Linux (CI runs them on a Linux runner). What is macOS-only sits behind a few seams: the install layout and installer (`AppInstaller`), the tool doctor's install hints, the CLI's data dir and `bin/fly`'s bundle layout, the window chrome and app menu, and the ⌘ shortcuts. A `Platform` value (`'mac' | 'linux'`) picks the behaviour at each seam; macOS behaviour stays exactly as it is.

**Tech Stack:** Electron 44, electron-builder 26 (deb target, fpm), NestJS DI, React 19, xterm.js, vitest, Stryker, GitHub Actions (`ubuntu-24.04`, `ubuntu-24.04-arm`).

**Spec:** the Design section below. There is no separate spec: the owner asked for the plan directly after the Linux/Windows discussion of 2026-10-29 (Linux first; Windows later through WSL2 running this same `.deb`).

## Design

Decided with the owner:

- **Maintainer:** the `.deb`'s `maintainer` is `Heron Labs <org@heronlabs.com.br>` (owner's choice; Debian requires one, and package.json's `author` has no email).
- Linux first. Windows is out of scope; a later step documents running the Linux `.deb` inside WSL2 (WSLg).

Planner's calls (the owner reviews them with the plan):

- **Package:** `.deb` only, x64 and arm64, each built on a runner of its own architecture (node-pty has no Linux prebuilds and compiles at `pnpm install`; `npmRebuild: false` packs that binary). No AppImage: it runs from a temporary mount, so a `fly` command linked into it breaks when the app quits. No rpm for now.
- **Install layout:** electron-builder's deb installs to `/opt/fly`; Electron is `/opt/fly/fly`, `bin/fly` is `/opt/fly/resources/bin/fly`.
- **`fly` command:** the package's post-install links `/usr/bin/fly` to `/opt/fly/resources/bin/fly` (electron-builder's default links it to the Electron binary, which is not the CLI). The wizard's command step only repairs the link, with `pkexec`.
- **Data:** Electron's `appData` on Linux is `$XDG_CONFIG_HOME` or `~/.config`, so app data lands in `~/.config/fly` (`fly-dev` for dev builds); the CLI reads the same path.
- **Tool doctor:** no Homebrew assumption on Linux. A missing `git`, `gh` or `tmux` shows the copyable `sudo apt install <tool>`; `claude` keeps its npm command.
- **Window:** native frame, `autoHideMenuBar: true`, the window icon from `resources/icon.png`; no traffic-light padding in the top bar or the wizard.
- **Menu (packaged, Linux):** only "fly" → "Configurar fly…" and "Sair" (no accelerator). The macOS edit and view menus would register Ctrl+C, Ctrl+R, Ctrl+Q… as window accelerators on Linux, taking those keys from the terminal.
- **Shortcuts on Linux:** Ctrl replaces ⌘ (Ctrl+N, Ctrl+Shift+F, Ctrl+S, Ctrl+Enter), but a key pressed in the terminal stays with the terminal. Terminal copy and paste are Ctrl+Shift+C and Ctrl+Shift+V; the paste keeps the image-to-PNG behaviour.
- **Unsupported platforms:** anything but darwin and linux fails at start with `Plataforma não suportada: <platform>`.
- **Updates:** the footer notice already links to the Release page; on Linux the user downloads the new `.deb` and runs `sudo apt install ./fly-….deb` again with fly closed.

## Global Constraints

- Start after the `improvements-fixes` pull request merges: rebase `feat-linux` on `main` first (it brings `AGENTS.md`, `scripts/sign-mac.ts` and the signing steps of the CD workflow).
- macOS behaviour, copy and packaging do not change. Existing mac tests keep their assertions; only call signatures that gain a `platform` argument change.
- UI copy and thrown errors in pt-BR; code, comments, commits and docs in English.
- Layer rules (`pnpm dep:cruise`): `application/ui` imports only `application/ui` and type-only `core/domain`; `preload.ts` only `core/domain`; `infrastructure` only `core/interfaces` and `core/domain`.
- Test isolation as in AGENTS.md "Testing": private tmux socket, mkdtemp dirs, mocked `gh` and `CommandRunner`, never the real `~/.claude` or app data.
- 100% coverage; Stryker at 100% on every changed file it mutates (`pnpm stryker run stryker.conf.json --mutate '<files>'`).
- Never edit `version.txt` or `CHANGELOG.md`. One commit per task, Conventional Commits with a scope.
- Before the pull request: `pnpm typecheck`, `pnpm lint:check`, `pnpm dep:cruise`, `pnpm test:unit`, `pnpm test:di`, `pnpm build`.

## Review Focus

1. **Ctrl+C in a Linux terminal tab interrupts `claude`.** Nothing (menu accelerator, shortcut handler, copy binding) may take it. Pinned by Task 5 (Linux menu has no edit/view menu) and Task 6 (shortcuts ignore keys from `.xterm`; copy is Ctrl+Shift+C); Task 9 checks it by hand.
2. **`XDG_CONFIG_HOME` set (or set to empty).** The CLI and the app must agree on the data dir, or `fly ls` misses tasks. Task 3 tests both.
3. **Ubuntu 24.04 restricts unprivileged user namespaces through AppArmor.** The app must still start after `apt install`. The custom post-install keeps electron-builder's sandbox and AppArmor steps verbatim (Task 7 test); Task 9 launches the GUI.
4. **A Linux machine without Homebrew and with a tool missing.** The wizard shows `sudo apt install <tool>` and never an "Instalar com brew" button. Tasks 2 and 4 test it.
5. **Updating the `.deb` while fly runs.** dpkg replaces `/opt/fly` under the running app. README says to close fly first (Task 8); tmux sessions survive either way.
