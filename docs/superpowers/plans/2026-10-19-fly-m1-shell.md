# fly M1 — Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the `heronlabs/fly` Electron app: repo scaffold with heronlabs conventions and CI, heronlabs theming (dark/light), workspace discovery (repos two levels deep plus every git worktree), and the worktrees column of the cockpit with a folder picker, recent roots and "Abrir no VSCode".

**Architecture:** Electron main process hosts a NestJS application context that wires `core` services to `infrastructure` adapters and exposes them to the renderer through typed IPC handlers (`application/ipc`) and a `preload.ts` contextBridge. The renderer (`application/ui`, React) only talks to `window.fly`. Layers and dependency rules follow roost/env-ssm, enforced by dependency-cruiser.

**Tech Stack:** Electron, electron-vite (swcPlugin for decorators), TypeScript ~5.8, React 19, zustand, NestJS 11 (`@nestjs/core` application context), vitest 4 (node + jsdom projects), @testing-library/react, gts + eslint, dependency-cruiser, pnpm 10, `@ant-design/icons`, `@fontsource/*`.

**Spec:** `docs/superpowers/specs/2026-10-19-fly-design.md` (milestone 1 of 6; terminal, queue state, diff/PR, editor and packaging are later plans).

## Global Constraints

- Layout `src/{application,core,infrastructure}` with `src/main.ts` and `src/preload.ts`; renderer under `src/application/ui`. Kebab-case files, `-service.ts` / `-handler.ts` / `-module.ts` suffixes.
- Dependency rules (spec §5.2): `core` never imports `application`; `application` never imports `infrastructure` except `src/application/ipc/ipc-module.ts`; `infrastructure` never imports `application` or `core` (except `core/interfaces` and `core/domain`, which adapters implement and return); `application/ui` imports only `application/ui` and type-only `core/domain`; `preload.ts` imports only `core/domain`.
- Node `>=22` (`.node-version` = `22.22.0`), pnpm `>=10` (`packageManager` = `pnpm@10.30.3`), TypeScript `~5.8`, strict, `noUncheckedIndexedAccess`.
- Lint: gts + `simple-import-sort` + jsonc/yml, same `eslint.config.ts` shape as roost. Tests: vitest, `tests/**/*.spec.ts(x)`, 100% coverage thresholds on `src/core`, `src/infrastructure`, `src/application/ipc/handlers`; `main.ts`, `preload.ts`, `ipc-module.ts` and `src/application/ui/**` excluded from thresholds in M1 (TODO raise in M5).
- No hardcoded workspace paths. No `~/Workfolder`. M1 opens one root at a time; several roots in one window (spec D11) is deferred to a later plan.
- Design system: vendored copy of `webapps/packages/pkg-design-system/src/tokens/index.ts` at `src/application/ui/theme/tokens.ts` with a `// TODO(fly): replace with @heronlabs/design-system once published` header. Icons from `@ant-design/icons`. Fonts bundled: JetBrains Mono (mono), Nunito Sans (body), MuseoModerno (display).
- UI copy in pt-BR as in the prototype: "Nova tarefa", "Abrir no VSCode", "Abrir pasta", "Recentes", "Esperando você", "Agente rodando", "CI", "Falhou".
- Git flow (spec D12): Task 1 lands on `main` by hand (bootstrap). From Task 2 on, all work happens on branch `feat-m1-shell`; the plan ends with a PR, never a push to `main`. `version.txt` is never edited.
- Package: `@heronlabs/fly`, `productName` `fly`, `appId` `com.heronlabs.fly`, license MIT, repo public.

## Review Focus

1. A root folder with zero git repos: the app shows the empty state ("Nenhum repositório em <root>") and the picker again, never a blank window or an unhandled rejection. Test in Task 6 (`WorkspaceService`) and Task 11 (`WelcomePanel`).
2. One repo whose `git worktree list` fails (git missing, corrupted `.git`): that repo is listed with `worktrees: []` and `error` set; every other repo still resolves. Test in Task 6.
3. Detached HEAD worktree (`branch: null`): the row shows the short SHA, no crash on `.replace` of null. Tests in Task 5 (parser) and Task 10 (panel).
4. Corrupted or missing `config.json`: app starts with defaults and overwrites on next save. Test in Task 7.
5. `code` CLI not on PATH: "Abrir no VSCode" falls back to `open -a "Visual Studio Code"`; both failing surfaces an error string to the renderer instead of a silent no-op. Test in Task 8.
6. Paths with spaces or unicode in porcelain output and in root folders: parsed and displayed unchanged. Test in Task 5.

  export type DirEntry = {name: string; isDirectory: boolean; isFile: boolean};
