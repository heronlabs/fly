# fly M3 — Queue State Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show each worktree's queue state in the tree and the footer: waiting for me, agent running, CI, failed, ready to merge, merged, idle, or unknown. The state is derived from Claude Code transcripts, `gh pr list` and `.supera/plan.md`. "Nova tarefa" sessions bind to the worktree their own transcript enters, not by creation order.

**Architecture:**
- **Transcript reading (infrastructure):** a pure parser turns transcript JSONL lines into a domain `TranscriptSummary`. An incremental reader (`TranscriptSource` port, `ClaudeTranscriptService`) tails `<projects>/<encoded cwd>/<uuid>.jsonl` from a saved byte offset. It follows `/clear` successors and maps sessions fly did not start best-effort (D8a).
- **Pull requests:** a `PrGateway` (`GhCliService`) lists PRs per repo.
- **Rules (core):** pure rules in `queue-rules.ts` classify a summary at time `now`. They combine session activity, the PR and plan presence into one `QueueStatus` using the spec's precedence. `QueueService` assembles a `QueueSnapshot`.
- **IPC:** `QueueHandler` polls every 3 s (PRs every 30 s) and broadcasts changes.
- **Renderer:** the snapshot feeds the status dot, a badge and the footer counts.
- **Binding:** `TaskService.bind` binds a task session to the first `.worktrees/<slug>` cwd in its transcript.

**Tech Stack:** M2 stack, no new dependencies. External tools: `gh` (authenticated); transcripts from Claude Code 2.1.278 or later.

**Spec:** `docs/superpowers/specs/2026-10-19-fly-design.md` (milestone 3 of 6: D8, D8a, D8b, §5.3 step 6, §5.4, §5.6, §7). Diff/PR panel and receipt display are M4; the doctor is M6.

**Spike:** `docs/superpowers/specs/2026-10-20-fly-transcript-spike.md`. Its "Parser contract" section binds Tasks 2–4. This plan only lists where it adds to or departs from that contract.

- So no `send-keys` fallback is needed.

## Global Constraints

- Every M1/M2 constraint still holds: layer and dependency rules, 100% coverage on `src/core`, `src/infrastructure` and `src/application/ipc`, kebab-case files with `-service`/`-handler`/`-module` suffixes, pt-BR copy, no hardcoded paths. Tests that touch tmux use a private `-L fly-test-<hex>` socket and kill it.
- The transcripts root is `<CLAUDE_CONFIG_DIR or ~/.claude>/projects`. It is injected through the `CLAUDE_PROJECTS_DIR` token. Tests use an `mkdtemp` directory and **never read the real `~/.claude`**.
- Project dir name = launch cwd with every char outside `[A-Za-z0-9]` replaced by `-` (spike §1).
- Transcript reading rules:
  - Read-only, always: fly never writes under the projects dir.
  - Incremental from a saved byte offset; whole files are never re-read on each poll.
  - File order, never timestamp order.
  - Unknown `type`s and fields are ignored, and a malformed line is skipped.
  - Every field is type-checked before use. A shape the rules don't recognise degrades to `unknown`; nothing throws to the UI (spec §7).
- PR source (D8): `gh pr list --state all --limit 50 --json number,url,headRefName,state,isDraft,mergeable,reviewDecision,statusCheckRollup`, run in the repo root with a 15 s timeout every 30 s. Only repos with at least one non-main worktree on a branch are polled. Never `gh pr view` per worktree.
- supera is not modified (D8). fly reads its contracts: `.worktrees/<slug>`, `.supera/plan.md` at the worktree root, and `receipt.schema.json`.
- Status values: `idle | engineer | waiting | ci | failed | ready | merged | unknown`. Precedence, highest first: `failed, ready, waiting, engineer, ci, unknown, idle, merged`.
- pt-BR copy (new):
  - Status titles: "Parado", "Agente rodando", "Esperando você", "CI rodando", "Falhou", "Pronto para merge", "Merged", "Estado desconhecido".
  - Badges: `eng`, `você`, `CI`, `falhou`, `merge`, `merged`, `?`.
  - Messages: "gh não encontrado — instale com: brew install gh", "gh não autenticado — rode: gh auth login".
  - The footer keeps its M1 labels.
- Git flow: branch `feat-m3-queue` from `main`. The plan ends with a PR; never push to `main`; `version.txt` untouched. Commits end with the session's `Co-Authored-By` trailer.
- Test commands:
  - Targeted runs: `pnpm vitest run --project <node|ui> <paths>`.
  - Gate: `pnpm typecheck && pnpm lint:check && pnpm dep:cruise && pnpm test:unit && pnpm test:di && pnpm build`.
  - Tasks 1–5 add modules that `main.ts` does not reach yet. Until Task 6 wires `TranscriptSource` and Task 8 wires `PrGateway`/`QueueHandler`, the gate tolerates only `no-unreachable-from-entry`/`no-orphans` on this plan's new modules.

## Planning rulings

Each ruling: decision, then what it costs if wrong.

- **P1.** Transcripts are polled every 3 s, and a file is read only when its size changed. The spec's fs.watch is not used, so there is no watcher lifecycle for directories that come and go. Cost: up to 3 s latency.
- **P2.** The line format (reducer) lives in infrastructure; the time-based rules (`classifyActivity`) live in core. Cost: none.
- **P3.** The footer's "Esperando você" counts `waiting + ready`; both need the human. Cost: the count is higher than the prototype's ready-only count.
- **P4.** Precedence places `unknown` between `ci` and `idle`. PR states don't depend on session liveness. `idle` = no activity and no PR state. Cost: none.
- **P5.** `.supera/plan.md` only turns an `unknown` activity into `engineer`. Cost: none.
- **P6.** Two time limits:
  - A background shell counts for 60 min after launch, so dev servers don't pin "agent running".
  - Mid-turn with no open tool and no new line for 10 min reads as `unknown`, which catches a vanished `turn_duration`.

  Cost: a 60+ min `gh pr checks --watch` reads as waiting.
- **P7.** An external session with no transcript since its creation (a plain shell) adds no activity, so its worktree shows idle, not `unknown`. Cost: an external claude whose transcript can't be located shows idle.
- **P8.** Binding uses transcript evidence first, which ignores the baseline. The creation-order fallback applies only when the repo has exactly 1 pending task and exactly 1 new worktree. Cost: if Claude Code stops tracking `cwd`, parallel tasks stay unbound (visible, never wrong).
- **P9.** PR mapping:
  - Checks: `CANCELLED`, `TIMED_OUT`, `ACTION_REQUIRED`, `STARTUP_FAILURE`, `STALE` and any other non-success conclusion count as failing.
  - Green checks that are draft, `REVIEW_REQUIRED` or `CHANGES_REQUESTED` → `waiting`.
  - `mergeable: UNKNOWN` → `ci`.

  Cost: a superseded cancelled run can show "falhou" until the next poll.
- **P10.** The receipt comes through spike §8 channels 1–3 and is exposed on the snapshot for M4. Channel 4 (subagent files) is deferred. Cost: about 34 of 294 historical engineer runs had no receipt in the parent, so they show none.
- **P11.** `gh` is polled every 30 s whether or not the window is focused (spec §9 leaves this to the builder). Cost: background API use.
- **P12.** `CLAUDE_CONFIG_DIR` is read from the app's environment; the login-shell env loads only PATH/LANG. Cost: a custom `CLAUDE_CONFIG_DIR` set in `.zshrc` is missed when fly is launched from Finder.
- **P13.** A worktree absent from the snapshot (before the first load) renders `idle`. Cost: no state flashes `?` at startup.
- **P14.** A silent pr-watch exit keeps "agent running" for up to 25 min (spike rule 4b). An optional supera change, pr-watch calling `ScheduleWakeup({stop:true})`, would make this exact; that is the user's call and outside this plan. Cost: a stale "eng"/"CI" badge for up to 25 min.

## Review Focus

1. **`/clear` in the middle of a fly session.** The state follows the new file once its first prompt carries `session_id`; until then the old file's state shows. Tests: Task 4 (successor cases).
2. **`gh` missing, logged out, or one repo failing.**
   - Transcript states still show.
   - The footer shows the message.
   - A failing repo keeps its last PR list.

   Tests: Task 5 (errors), Task 7 (status, message, previous list kept), Task 9 (footer message).
3. **Two "Nova tarefa" in one repo whose worktrees appear in the other order.**
   - Each session binds to the worktree its own transcript entered.
   - While two tasks of a repo are pending, binding never falls back to a guess.

   Test: Task 6.
4. **Large or growing transcripts.** These cases give the correct summary and never throw, and only appended bytes are read:
   - a 1.5 MiB line;
   - a half-written last line;
   - a UTF-8 char split across reads;
   - a truncated or replaced file;
   - a malformed line.

   Tests: Task 2 (malformed, wrong-typed fields), Task 4 (tail cases).
5. **A session fly did not start (Termius) sharing a cwd with another live claude.** It shows `?`, never another session's state; a plain shell with no claude shows nothing. Tests: Task 4 (`forDirectory`), Task 7 (external sessions).

  // core/domain/queue.ts
  export type QueueStatus = 'idle' | 'engineer' | 'waiting' | 'ci' | 'failed' | 'ready' | 'merged' | 'unknown';
  export type ChecksState = 'none' | 'pending' | 'passing' | 'failing';
  export type PullRequest = {
    number: number; url: string; branch: string;
    state: 'open' | 'merged' | 'closed'; draft: boolean;
    mergeable: 'mergeable' | 'conflicting' | 'unknown';
    review: 'approved' | 'changes-requested' | 'required' | 'none';
    checks: ChecksState;
  };
  export type WorktreeQueue = {worktreeId: string; status: QueueStatus; pullRequest: PullRequest | null; receipt: ReceiptResult | null};
  export type QueueSnapshot = {github: 'ok' | 'missing' | 'error'; message: string | null; worktrees: WorktreeQueue[]};

  // core/domain/transcript.ts
  export type Receipt = {summary: string; filesChanged: string[]; verification: Record<string, 'pass' | 'fail' | 'skipped'>; notes?: string};
  export type ReceiptResult = {kind: 'valid'; receipt: Receipt} | {kind: 'invalid'; problems: string[]};
  export type TranscriptSummary = {
    phase: 'none' | 'mid-turn' | 'turn-ended';
    asking: boolean;            // an AskUserQuestion tool_use is open
    openTools: number;
    lastEventAt: number | null; // ms
    wakeupAt: number | null;    // ms (toolUseResult.scheduledFor)
    looping: boolean;
    lastTurnEndAt: number | null;
    backgroundAgents: number;
    backgroundShells: number[]; // launch times (ms) of shells with no completion yet
    launchCwd: string | null;
    worktreePath: string | null;
    receipt: ReceiptResult | null;
  };
  export type Activity = 'waiting' | 'running' | 'scheduled' | 'unknown';

  // core/services/queue-rules.ts
  export const WAKEUP_GRACE_MS = 20 * 60_000;
  export const LOOP_FALLBACK_MS = 1_500_000;
  export const SHELL_WINDOW_MS = 60 * 60_000;
  export const STALL_MS = 10 * 60_000;
  export const PRECEDENCE: readonly QueueStatus[]; // the Global Constraints order
  export const classifyActivity: (summary: TranscriptSummary | null, now: number) => Activity;
  export const pullRequestStatus: (pr: PullRequest | null) => QueueStatus | null;
  export const worktreeStatus: (input: {activities: Activity[]; pullRequest: PullRequest | null; hasPlan: boolean}) => QueueStatus;
  ```
- `classifyActivity`, first match wins (spike "Classification", plus P6):
  1. Summary `null` or phase `none` → `unknown`.
  2. `asking` → `waiting`.
  3. Phase `mid-turn`: if `openTools === 0`, `lastEventAt !== null` and `now - lastEventAt > STALL_MS`, → `unknown`; else → `running`. A `null` `lastEventAt` is never stale; the spike fixtures carry no timestamps.
  4. Phase `turn-ended`:
     - `wakeupAt` set: `now <= wakeupAt + WAKEUP_GRACE_MS` → `scheduled`, else → `unknown`.
     - `looping` and `now <= lastTurnEndAt + LOOP_FALLBACK_MS` → `scheduled`.
     - `backgroundAgents > 0` → `running`.
     - Any shell with `now - launch <= SHELL_WINDOW_MS` → `scheduled`.
     - Otherwise → `waiting`.
- `pullRequestStatus`:
  - `null`/`closed` → `null`.
  - `merged` → `merged`.
  - Open PR:
    - checks `failing` or `conflicting` → `failed`;
    - checks `pending` or mergeable `unknown` → `ci`;
    - `draft`, or review `required`/`changes-requested` → `waiting`;
    - else → `ready`.
- `worktreeStatus`:
  1. Collect the candidates:
     - `pullRequestStatus(pr)` when non-null.
     - One candidate per activity: `waiting`→`waiting`, `running`→`engineer`, `scheduled`→`ci` when the PR is open and `engineer` otherwise, `unknown`→`unknown`. With `hasPlan`, `unknown`→`engineer` (P5).
  2. Pick the first candidate in `PRECEDENCE`.
  3. No candidates → `idle`.

- The parser implements the spike's "Reducer state" and "Line to event mapping" as written, with these additions:
  - **Phase.** `prompt`, `toolResult` and `assistant` → `mid-turn`. `turnEnd`, `interrupt` and `localCommand` → `turn-ended`. `scheduled_task_fire` → `mid-turn`. `none` until the first mapped line.
  - **`lastEventAt`** = `Date.parse(timestamp)` of the latest line that changed the phase or the open-tool map. A line without a timestamp keeps the previous value.
  - **Cwd fields.** `launchCwd` = the first line carrying a string `cwd`. `worktreePath` = from the first line whose `cwd` starts with `${launchCwd}/.worktrees/`, it is `${launchCwd}/.worktrees/<next path segment>`. It never changes afterwards.
  - **Background shells.** A shell's launch time is its tool_result's timestamp. Monitor's `toolUseResult.taskId` counts only when the open tool for that `tool_use_id` was `Monitor`.
  - **ScheduleWakeup results.** `scheduledFor` is read only when it is a number. "Stopped" means `toolUseResult.stopped === true`.
  - **Task notifications.** A user line whose string content starts with `<task-notification>` is a `prompt`, and it removes matching background shells (spike `bgShells`). `parseTaskNotification` reads the tags `task-id`, `tool-use-id`, `status` and `result` (inner text, raw, not unescaped).
  - **Defensive reads.** A non-object line, or a wrong-typed `message`/`content`/`toolUseResult`, leaves the state unchanged and never throws. A tool_result whose id is not open is still a `toolResult` for the phase, and its Bash `backgroundTaskId` still registers a shell. The spike's T9 fixture has no launching `tool_use` line.

  // core/interfaces/transcript-source.ts
  export abstract class TranscriptSource {
    // The transcript a fly-started session writes, following /clear successors; null until it exists.
    abstract forSession(input: {launchCwd: string; sessionId: string}): Promise<TranscriptSummary | null>;
    // D8a best effort for a session fly did not start.
    abstract forDirectory(input: {cwd: string; since: number; exclude: string[]; now: number}): Promise<TranscriptSummary | 'ambiguous' | null>;
  }
  // infrastructure/claude/tokens.ts
  export const CLAUDE_PROJECTS_DIR = Symbol('CLAUDE_PROJECTS_DIR');
  // infrastructure/claude/claude-transcript-service.ts
  export const projectDirName: (cwd: string) => string;
  export const LIVE_WINDOW_MS = 10 * 60_000;
  @Injectable() export class ClaudeTranscriptService extends TranscriptSource {
    constructor(@Inject(CLAUDE_PROJECTS_DIR) projectsDir: string) {}
  }
  ```
- **Tail** (per file path; at most 64 cached files, least recently read evicted):
  - Each cache entry keeps `{ino, offset, remainder: Buffer, parser}`.
  - A read `stat`s the file. On ENOENT it returns `null`.
  - If `size < offset` or the inode changed, the entry restarts from 0 with a new parser.
  - Bytes `[offset, size)` are read through a `FileHandle` in chunks of at most 1 MiB, after the remainder.
  - Bytes up to the last `\n` are decoded as UTF-8, split into lines and pushed. The bytes after it stay in `remainder`.
- **`forSession`:**
  - The file lives in `<projectsDir>/<projectDirName(launchCwd)>`. The current file is the recorded successor, else `<sessionId>.jsonl`.
  - **Successor check:**
    - Candidates are the other `*.jsonl` files with an mtime later than the current one's.
    - A file's owner is the first string `session_id` found in the complete lines of its first 256 KiB.
    - The owner is cached once found. It is also cached as "none" once 256 KiB were scanned without one. A smaller file without it is re-checked on the next call.
    - The newest file owned by `sessionId` becomes the current file.
  - A missing dir → `null`.
- **`forDirectory`:**
  - Candidates are the `*.jsonl` files with mtime ≥ `since`, excluding any file whose stem is in `exclude` or whose owner is in `exclude`.
  - Live candidates are those with mtime ≥ `now - LIVE_WINDOW_MS`.
  - More than 1 live candidate → `'ambiguous'`.
  - Otherwise, the newest candidate's summary; no candidates → `null`.
- Errors other than ENOENT reject; callers map them to `unknown`.
